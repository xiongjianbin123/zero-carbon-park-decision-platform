# 零碳园区全过程决策与申报咨询平台设计规格

## 1. 产品目标

本产品面向山西资源型工业园区管委会领导、项目负责人和咨询团队，用六个可自由浏览、也可按顺序汇报的页面，回答以下决策问题：

1. 园区当前是什么底子；
2. 2026—2030 年应该怎么建设；
3. 重点项目走到哪个环节、卡在哪里；
4. 能申报什么政策、还缺什么材料；
5. 总投资如何拆解、资金从哪里来；
6. 领导追问时，数字依据是什么。

首个版本是可独立交付的领导演示产品，不接真实外部业务系统。所有业务数字来自一个统一、可读、可修改的本地配置文件，页面刷新后保持稳定。

## 2. 已确认范围

### 2.1 六个页面

| 序号 | 页面 | 核心任务 |
| --- | --- | --- |
| 01 | 园区驾驶舱 | 展示园区综合态势、零碳转型关系、风险与机会 |
| 02 | 零碳建设路径 | 展示 2026—2030 年路线、年度里程碑和技术组合 |
| 03 | 全过程项目地图 | 展示重点项目的全生命周期节点、责任单位、材料缺口和风险建议 |
| 04 | 政策与申报中心 | 展示政策机会池、匹配度、截止窗口和申报材料完整度 |
| 05 | 投资与资金地图 | 展示 67 亿元投资拆解、资金来源、已落实资金和缺口 |
| 06 | 领导问数 | 用预置问题提供确定性、可追溯的证据化回答 |

### 2.2 交付方式

- 默认直接进入园区驾驶舱，不设置登录页。
- 顶部导航支持六页自由浏览。
- “引导汇报”入口按 01—06 顺序切换页面，并显示当前页、汇报要点、上一页和下一页。
- 提供 macOS 本地一键启动脚本。
- 提供静态构建命令和可复制部署的 `dist/` 构建包。

### 2.3 明确不做

- 不修改“源网荷储一体化管控云平台”和 `vpp-app`；它们仅作视觉参考。
- 不接数据库、联网政策搜索、大模型、真实文件解析、用户权限或在线编辑后台。
- 不用随机数、当前时间或接口回退生成业务数据。
- 不宣称演示数据为真实园区成果；页面固定标注“演示数据”。

## 3. 信息架构与导航

应用使用 Vue 3 单页架构和 Hash 路由，保证静态文件直接部署后仍可访问。路由固定如下：

- `#/dashboard`
- `#/roadmap`
- `#/projects`
- `#/policies`
- `#/investment`
- `#/qa`

根路由和未知路由均重定向到 `#/dashboard`。应用外壳负责顶部品牌、六项导航、园区名称、数据基准日、演示标记和引导汇报控制；页面只负责各自的业务表达。

## 4. 视觉系统

### 4.1 视觉定位

视觉延续“源网荷储一体化管控云平台”的能源调度大屏气质，并以用户指定的 `vpp/load/price` 页面为直接参考：深蓝夜幕底、青色能量线、多彩业务状态和高密度图表。六页必须使用同一应用外壳、同一背景和同一面板语言，不能出现浅色内页。

### 4.2 色彩令牌

| 名称 | 色值 | 用途 |
| --- | --- | --- |
| 夜幕底色 | `#061229` | 全局页面背景 |
| 深海层 | `#0A1A3A` | 内容底层、图表内底 |
| 面板蓝 | `#0E2148` | 卡片和浮层 |
| 能量青 | `#00E5FF` | 主操作、当前态、关键连线 |
| 电力蓝 | `#4EB8FF` | 次级指标、金融来源 |
| 达成绿 | `#7BD877` | 已完成、正向结果 |
| 机会橙 | `#F5A623` | 政策窗口、资金机会、提醒 |
| 风险粉 | `#FF6B9D` | 风险、缺口、异常 |
| 信息文字 | `#B8D4F0` | 正文和说明 |
| 标题白 | `#F4FBFF` | 标题和核心数字 |

彩色文字必须编码业务含义，不能随机上色：青色表示当前与总览，绿色表示完成或收益，橙色表示机会或待处理，粉色表示风险或缺口。

### 4.3 字体与字号

- 中文标题：`"PingFang SC", "Microsoft YaHei", sans-serif`，字重 700—800。
- 数字与英文：`"DIN Alternate", "Roboto Mono", monospace`。
- 桌面端正文不得小于 14px，主要导航不得小于 15px，卡片核心数字为 28—36px，页面标题为 24—30px。
- 小屏仅缩减布局和间距，不将正文压到 12px 以下。

### 4.4 结构与标志性动效

- 全局背景使用深蓝渐变、低对比网格和顶部径向蓝光。
- 面板使用半透明深蓝渐变、细青色边框、发光角标和轻内阴影。
- 每页标题前使用发光状态点；重要数字允许轻微文字辉光。
- 唯一贯穿六页的标志性动效是面板顶部缓慢流动的“能量脉冲线”。当前节点可低频呼吸，图表只在首次进入时顺序显现。
- `prefers-reduced-motion: reduce` 时关闭脉冲、呼吸和入场动画。

## 5. 页面设计

### 5.1 园区驾驶舱

顶部显示规划总投资 67.0 亿元、目标绿电率 43%、专项资金空间 9.4 亿元、关键风险 4 项。主体左侧是“园区决策中枢”关系图，关联光伏 62MW、储能 100MW/200MWh、绿电缺口 1.7 亿 kWh、节能潜力 11%；右侧按风险、机会、成果三类展示接入容量、政策匹配和年减排潜力。页面承担开场陈述，首屏无需滚动即可读完。

### 5.2 零碳建设路径

页面展示 2026—2030 五年时间轴：2026 能源审计与碳盘查，2027 光储建设，2028 绿电交易与 VPP，2029 工业节能改造，2030 验收达标。右侧技术组合环展示新能源、储能、能效和碳管理。点击年份更新下方年度目标、项目和预期贡献，不跳转路由。

### 5.3 全过程项目地图

页面以“重点项目列表 + 生命周期节点 + 节点详情”表达。默认选中储能示范项目，生命周期包含策划、立项、备案、可研、选址、土地、环评、能评、接入、设计、资金、招采、施工、并网、验收和运营。点击项目或节点时，详情区同步显示状态、责任单位、需要材料、已完成材料、缺口、风险和建议。未启动节点只显示明确的待启动状态，不伪造进度。

### 5.4 政策与申报中心

左侧政策机会池至少包含国家级零碳园区试点、节能降碳专项资金、超长期特别国债和绿色低碳示范，显示匹配度、预计支持、截止时间和条件级别。点击政策后，右侧显示匹配理由以及 17 项条件清单，状态只允许“已满足、待补、缺失”。默认政策完整度为 14/17，并明确列出两项待补和一项缺失。

### 5.5 投资与资金地图

顶部显示总投资 67.0 亿元、主体已明确 31.0 亿元、专项空间 9.4 亿元、资金缺口 18.6 亿元。左侧树图展示新能源、储能、工业节能等投资板块；点击板块显示项目、规模和成本构成。右侧环图展示社会资本、央国企、金融机构、财政专项和待落实资金。所有分项加总必须与配置中的总额一致，测试自动校验。

### 5.6 领导问数

页面提供至少 12 个领导常问问题，首版使用配置驱动的确定性答案，不调用模型。点击问题后显示：一句结论、彩色关键数字、三条以内依据、建议动作、证据标签和基准日。每个关键数字必须能关联到配置中的指标或项目；无法匹配的问题不自由生成答案，而是提示用户从预置问题中选择。

## 6. 引导式汇报

点击“开始引导汇报”后进入覆盖在当前页面上的轻量汇报条，不进入独立模式。每页配置一个标题、一句领导结论和 2—3 个讲解要点。用户可使用上一页、下一页、退出汇报，也可继续点击顶部导航；导航后汇报条自动同步到对应页。刷新页面后回到自由浏览状态。

## 7. 数据与配置

唯一业务数据源为 `src/config/park.ts`，导出只读 `parkConfig`。配置包含：

- `meta`：平台名、园区名、区域、产业类型、基准日、演示标记；
- `overview`：投资、用能、绿电率、排放、减排、风险等总览指标；
- `roadmap`：年度里程碑和技术组合；
- `projects`：项目、生命周期节点、责任单位、材料和风险；
- `policies`：政策、匹配度、资金空间、窗口和条件；
- `investment`：投资板块、项目明细和资金来源；
- `qa`：问题、答案、指标引用、证据和建议；
- `tour`：六页的汇报标题与要点。

展示组件不得自行硬编码业务数字。衍生值通过纯函数计算，关键校验包括总投资拆解、资金来源和项目缺口的加总一致性，以及问答引用 ID 的存在性。

## 8. 技术架构

- Vue 3 + TypeScript + Vite。
- Vue Router 使用 Hash 模式。
- ECharts 绘制环图、关系图、树图、进度条和趋势图；流程节点与时间轴使用原生 Vue/CSS，避免为了简单图形增加复杂图表配置。
- Pinia 不纳入首版；跨页状态仅有引导汇报状态，放在一个轻量 composable 中。
- 样式使用 CSS 变量和普通 scoped CSS，不引入第二套 UI 组件库。
- Vitest 验证配置、衍生计算和关键组件行为；Playwright 验证六页导航、交互和截图基线。

建议文件边界：

```text
src/
  app/                应用外壳、导航和汇报条
  components/         通用面板、指标卡、状态标签、图表容器
  config/park.ts      唯一业务数据源
  composables/        汇报状态和图表生命周期
  pages/              六个页面，每页一个目录
  router/             Hash 路由
  styles/             视觉令牌、全局背景、动效和响应式规则
  utils/              纯计算与配置校验
tests/
  unit/               配置、计算和组件测试
  e2e/                页面导航和交互测试
scripts/              本地一键启动与静态构建脚本
```

## 9. 响应式、可访问性与异常状态

- 首要验收视口为 1440×900；兼容 1920×1080、1280×720 和最小 768px 宽度。
- 1440px 以上保持大屏双栏结构；低于 1100px 时面板改为单列并允许纵向滚动。
- 所有交互元素使用真实 `button` 或链接，具有可见键盘焦点；图表外提供文本摘要和 `aria-label`。
- 配置校验失败时显示深色错误页，指出具体字段路径，不用空白页或伪造回退数据。
- 图表区域无数据时显示“统一配置中暂无数据”，不显示随机占位图。

## 10. 验收标准

1. 打开根地址直接进入驾驶舱，六个导航入口全部可用。
2. 六页使用相同的 `#061229` 深蓝底、顶部导航、面板和颜色语义。
3. 六页在 1440×900 下无文字重叠、卡片溢出或关键内容被遮挡。
4. 主文字字号符合本规格，关键数字具有明确而一致的颜色含义。
5. 路线年份、项目节点、政策条目、投资板块和预置问答均可点击并更新详情。
6. 引导汇报可从任意页面开始、前后切换、与自由导航同步并退出。
7. 所有业务数字只来自 `src/config/park.ts`，刷新页面不变化。
8. 投资、资金与问答引用通过自动一致性测试。
9. `npm run test`、`npm run test:e2e` 和 `npm run build` 全部通过。
10. 一键启动脚本可在本机启动应用，`dist/` 可由静态服务器直接访问所有 Hash 路由。
