# 园区申报与项目运营闭环 P1.1 设计规格

## 目标

在现有“园区建档 → 数据导入 → 指标诊断 → 任务与佐证 → 成果交付”P0 闭环上，补齐团队长期使用最需要的协作、核验和追踪界面。匿名示范驾驶舱、深蓝能源视觉、确定性指标计算和园区隔离规则保持不变。

## 本次范围

1. 园区管理员可在工作台查看成员、按邮箱邀请成员并调整项目角色。
2. 任务列表支持打开详情；详情中可编辑审核备注、查看佐证文件、下载文件并查看任务相关操作记录。
3. 新增“申报准备度”页面，按指标确定性汇总指标状态、关联任务、佐证数量和下一步动作。
4. 成果交付页显示当前园区历史成果，并允许重新下载可下载文件。
5. 项目总览增加任务状态分布、佐证覆盖率和申报准备度概览，不引入装饰性大卡片。

## 不在本次范围

- 不接入实时 EMS、VPP 或设备控制接口。
- 不新增数据库表，不改变现有指标口径。
- 不让 MiniMax 修改指标、任务、成员、文件或成果。
- DOCX 申报书组稿作为后续独立增量；本次先把其依赖的准备度矩阵和证据链做完整。

## 数据与接口

- 复用现有 `park_members`、`tasks`、`files`、`exports`、`audit_logs`。
- 增加只读查询：任务佐证列表、任务操作记录、成果历史列表。
- 所有查询继续先验证可信身份和园区成员关系；任务、文件、成果必须同时匹配 `park_id`。
- 前端准备度由最新诊断与任务数据确定性计算，不持久化派生结果。

## 页面结构

- 工作台导航增加“申报准备度”和“项目成员”。
- 任务详情使用右侧抽屉，保留列表上下文；移动端改为页面内全宽面板。
- 准备度页面采用“总览轨道 + 指标矩阵”，颜色沿用青色、绿色、橙色、粉色的能源状态语义。
- 概览页以细轨道和紧凑数据带表达项目状态，不使用大面积纯装饰模块。

## 验收标准

1. 管理员能邀请成员和调整角色；非管理员没有写操作。
2. 成员只能读取所属园区的数据，跨园区任务佐证、记录和成果查询返回拒绝或未找到。
3. 任务详情能显示真实佐证文件并下载；审核备注保存后刷新仍存在。
4. 每个诊断指标显示唯一准备状态，汇总数量与明细一致。
5. 历史成果刷新后仍能列出并下载；诊断打印快照明确标记为不可下载文件。
6. 桌面与 390×844 视口无横向溢出，键盘焦点可见，减少动态效果偏好受到尊重。
7. TypeScript、单元测试、服务测试、浏览器验收和生产构建全部通过。
